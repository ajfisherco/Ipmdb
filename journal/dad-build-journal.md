# DAD Build Journal

## Purpose

This journal records the build path for DAD — Dollar a Day, DADS — Dollar A Day Society, and the public-record workflow through IPM.db.

It is written so other people can see the path, copy the method, avoid the mistakes, and build their own public-interest contribution flow.

## Locked phrase

**Civic vending machine for hope.**

Meaning:

A simple public mechanism where small inputs create trackable community outcomes.

Context:

DAD is being shaped as a simple contribution stream. People contribute small amounts. The system records what comes in, where it goes, what happens, and what improves.

## Working stack

**AJF&Co.**

A Parent Company.

AJF&Co. is the build space and principal development holder.

**IPM.db**

The public record layer.

IPM.db records ideas, contributions, decisions, allocations, receipts, outcomes, and improvements.

**DAD — Dollar a Day**

The contribution face.

DAD presents the simple public ask: one dollar a day, one community at a time.

**DADS — Dollar A Day Society**

The society path.

DADS is the participation, structure, accountability, local service, and community delivery path.

## What was learned

Do not embed the full DAD page inside the AJF&Co. build page.

Use a button instead.

The build page should point to DAD.

The DAD page should contain DAD.

The public record should remain separate enough to stay readable.

## Practical method

1. Start with a plain public page.

2. Create one action button.

3. Make the contribution path obvious.

4. Keep the society path nearby.

5. Keep the public record visible.

6. Record every decision that becomes part of the flow.

7. Improve the wording in public as the structure gets clearer.

## Copy pattern

DAD is a companion initiative to IPM.db.

DAD supports receiptable giving through an eligible structure.

Contributions are recorded, receipts are issued where applicable, and the public record tracks contributions, allocations, and outcomes.

## Page-order lesson

Good order:

AJF&Co.

IPM.db.

Instant Submission.

DAD / DADS / Public Record buttons.

Nodes.

Concept links.

DAD should not interrupt the IPM.db flow by appearing as a full embedded page.

## Design lesson

Simple beats busy.

Buttons beat embeds.

A clean public path beats a perfect domain.

The system matters more than the handle.

## Carrd lesson

A Carrd button URL field must contain only a URL.

Do not paste HTML into a URL field.

Full HTML belongs in a Code / Embed element.

A button element only needs the link.

## GitHub / IPM.db lesson

Issues act as working records.

Labels keep the system searchable.

A public issue list can become a lightweight ledger.

Clean labels matter.

Useful labels include:

- DAD
- DADS
- IPM.db
- milestone
- Agreed
- locked
- site
- social
- definition
